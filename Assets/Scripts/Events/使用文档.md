# GameEvents 事件系统使用文档

## 一、系统概述

`GameEvents` 是一个**基于枚举的全局事件总线**，用于 Unity / .NET 项目中各模块间的松耦合通信。核心思想：**发布者不知道谁在监听，监听者不依赖发布者**。

### 核心特性

| 特性 | 说明 |
|------|------|
| 枚举分发 | 使用枚举值标识事件类型，避免字符串拼写错误 |
| 线程安全 | 订阅/发布/取消订阅均有 `lock` 保护 |
| 防重复订阅 | 同一处理器不会重复添加到委托链中 |
| 锁外回调 | 事件处理器在锁外执行，避免嵌套锁导致的死锁 |
| 零依赖 | 核心代码不依赖任何引擎特性，可跨平台使用 |

### 文件结构

```
events/
├── GameEvents.cs              # 核心事件总线（必须）
├── EventTypes_Template.cs     # 事件类型和参数类模板（按需修改）
├── GameLogTypes_Template.cs   # 游戏日志扩展模板（按需修改）
└── 使用文档.md                # 本文档
```

## 二、快速开始

### 步骤 1：复制核心文件

将 `GameEvents.cs` 复制到你的项目 `Scripts` 目录下。这是唯一必须的文件。

### 步骤 2：定义事件类型

```csharp
// 定义你的事件枚举
public enum MyEventType
{
    PLAYER_ON_LEVEL_UP,
    PLAYER_ON_DEATH,
    UI_ON_BUTTON_CLICK,
    GAME_ON_PAUSE,
    GAME_ON_RESUME,
}
```

### 步骤 3：定义事件参数类

```csharp
// 创建一个事件参数类（带数据的事件）
public class PlayerLevelUpEventArgs : GameEventBase
{
    public int PlayerId { get; }
    public int NewLevel { get; }

    public PlayerLevelUpEventArgs(int playerId, int newLevel)
    {
        PlayerId = playerId;
        NewLevel = newLevel;
    }
}

// 无需数据的简单事件可以直接用 GameEventBase
```

### 步骤 4：开始使用

```csharp
// ========== 订阅事件 ==========
// 通常在 OnEnable / Start 中订阅
GameEvents.Listen(MyEventType.PLAYER_ON_LEVEL_UP, OnPlayerLevelUp);

// ========== 取消订阅 ==========
// 通常在 OnDisable / OnDestroy 中取消订阅，防止内存泄漏
GameEvents.Unlisten(MyEventType.PLAYER_ON_LEVEL_UP, OnPlayerLevelUp);

// ========== 发布事件 ==========
var args = new PlayerLevelUpEventArgs(playerId: 1, newLevel: 10);
GameEvents.Publish(MyEventType.PLAYER_ON_LEVEL_UP, args);

// ========== 事件处理器 ==========
private void OnPlayerLevelUp(IGameEvent evt)
{
    var args = evt as PlayerLevelUpEventArgs;
    Debug.Log($"玩家 {args.PlayerId} 升级到了 {args.NewLevel} 级");
}
```

## 三、API 参考

### GameEvents 静态类

#### Publish — 发布事件

```csharp
public static void Publish(Enum eventType, IGameEvent evt)
```

| 参数 | 说明 |
|------|------|
| `eventType` | 事件类型枚举值，用于分发 |
| `evt` | 事件参数，需实现 `IGameEvent` 接口 |

#### Listen — 订阅事件

```csharp
public static void Listen(Enum eventType, GameEventHandler handler)
```

同一处理器重复订阅会被自动忽略（幂等操作）。

#### Unlisten — 取消订阅

```csharp
public static void Unlisten(Enum eventType, GameEventHandler handler)
```

当该事件类型没有任何监听器时，自动清理字典条目。

#### ClearAllListeners — 清空所有监听器

```csharp
public static void ClearAllListeners()
```

通常在场景切换或游戏退出时调用。

#### GetListenerCount — 获取监听器数量（调试）

```csharp
public static int GetListenerCount(Enum eventType)
```

#### GetAllEventTypes — 获取所有事件类型（调试）

```csharp
public static Enum[] GetAllEventTypes()
```

## 四、最佳实践

### 4.1 订阅与取消订阅配对

```csharp
public class PlayerUI : MonoBehaviour
{
    private void OnEnable()
    {
        GameEvents.Listen(EventType.PLAYER_ON_LEVEL_UP, OnLevelUp);
        GameEvents.Listen(EventType.PLAYER_ON_DEATH, OnDeath);
    }

    private void OnDisable()
    {
        // 务必取消订阅，否则对象销毁后触发事件会导致空引用
        GameEvents.Unlisten(EventType.PLAYER_ON_LEVEL_UP, OnLevelUp);
        GameEvents.Unlisten(EventType.PLAYER_ON_DEATH, OnDeath);
    }
}
```

### 4.2 事件类型命名规范

使用 **模块前缀 + 动作** 的命名方式：

```
模块_事件_ON_动作

GAME_EVENT_ON_START        ✅ 好的
PLAYER_EVENT_ON_LEVEL_UP   ✅ 好的
ITEM_EVENT_ON_PICKUP       ✅ 好的
OnPlayerDeath              ❌ 不好（无模块前缀）
event1                     ❌ 不好（无意义）
```

### 4.3 事件参数类命名

以 `EventArgs` 结尾，清晰表达携带的数据：

```csharp
PlayerLevelUpEventArgs     ✅
ResourceChangeEventArgs    ✅
ItemEventArgs              ✅
MyData                     ❌
Info                       ❌
```

### 4.4 避免在事件回调中发布可能形成循环的事件

```csharp
// ❌ 危险：可能形成 A→B→A 的无限循环
void OnPlayerDamage(IGameEvent evt)
{
    // 不要在伤害回调中再次发布伤害事件
    GameEvents.Publish(EventType.PLAYER_EVENT_ON_DAMAGE, new PlayerValueEventArgs(player, 10));
}
```

### 4.5 场景切换时清理

```csharp
// 场景卸载前清空所有事件
void OnDestroy()
{
    GameEvents.ClearAllListeners();
}
```

### 4.6 不建议在 Update 中高频发布事件

事件系统有 lock 开销，不适合每帧数百次的高频调用。高频场景建议使用 Unity 的 `Update` 直接轮询或使用 `Action` 直接回调。

## 五、常见使用模式

### 模式 1：模块间通信

```csharp
// 背包模块：物品被使用时发布事件
GameEvents.Publish(EventType.ITEM_ON_USE, new ItemEventArgs(item));

// 音效模块：监听物品使用，播放音效
GameEvents.Listen(EventType.ITEM_ON_USE, OnItemUsed);

// UI模块：监听物品使用，更新界面
GameEvents.Listen(EventType.ITEM_ON_USE, RefreshInventory);
```

### 模式 2：游戏日志系统

```csharp
// 记录游戏日志
var entry = new GameLogEntry
{
    index = currentIndex,
    phase = "Gameplay",
    action = GameLogAction.ItemPickup,
    sourceName = playerName,
    targetName = itemName,
    value = 1,
};

GameEvents.Publish(EventType.LOG_EVENT_ENTRY, new GameLogEventArgs(entry));

// UI 层监听并展示
GameEvents.Listen(EventType.LOG_EVENT_ENTRY, OnGameLog);
```

### 模式 3：状态机/流程管线

```csharp
// 通过事件管线串联游戏流程
void StartGame()
{
    GameEvents.Publish(EventType.GAME_EVENT_ON_START, new GameStateEventArgs("Starting"));
    // 初始化 → 加载场景 → 生成玩家 → 开始游戏
    GameEvents.Publish(EventType.SCENE_EVENT_ON_LOADED, new SceneEventArgs("Level1"));
    GameEvents.Publish(EventType.PLAYER_EVENT_ON_SPAWN, new PlayerEventArgs(player));
}
```

### 模式 4：无数据事件

```csharp
// 不需要传数据时，直接用 GameEventBase
public enum SimpleEvent { GAME_PAUSE, GAME_RESUME }

// 发布
GameEvents.Publish(SimpleEvent.GAME_PAUSE, new GameEventBase());

// 订阅
GameEvents.Listen(SimpleEvent.GAME_PAUSE, evt => {
    Time.timeScale = 0;
});
```

## 六、如何接入新项目

### Unity 项目

1. 将 `GameEvents.cs` 放入 `Assets/Scripts/` 目录
2. 创建你的事件枚举文件（参考 `EventTypes_Template.cs`）
3. 将模板中的 `object` 类型替换为你的实际类型

### 纯 .NET 项目

1. 将 `GameEvents.cs` 复制到项目中
2. `GameEventBase` 会自动使用 `DateTime` 获取时间戳（通过 `#if UNITY_ENGINE` 预编译指令）
3. 无需任何额外依赖

## 七、注意事项

| 问题 | 说明 |
|------|------|
| 内存泄漏 | 忘记 `Unlisten` 是内存泄漏的常见原因，务必在对象销毁时取消订阅 |
| 委托链过期 | 如果回调引用了已销毁的 GameObject，调用时会抛异常。用 `OnDisable` 取消订阅来解决 |
| 性能 | 单次 Publish 是 O(1) 查找+O(n) 遍历，n = 监听器数量。不要在 Update 中高频使用 |
| 线程 | Publish 是线程安全的，但回调中不应修改事件字典（由锁外回调保证安全） |

## 八、扩展建议

### 添加事件优先级

如果需要按优先级顺序执行监听器，可以在 `IGameEvent` 中扩展：

```csharp
public interface IGameEvent
{
    int Priority { get; }  // 数字越小越先执行
}
```

### 添加事件过滤

```csharp
public static void Listen<T>(Enum eventType, Action<T> handler) where T : IGameEvent
{
    Listen(eventType, evt => {
        if (evt is T typed) handler(typed);
    });
}
```

---

> 核心原则：**高内聚、低耦合**。事件只是通知机制，不要在事件回调中做过于复杂的业务逻辑。每个模块应该自闭环，事件只传递必要的信息。
